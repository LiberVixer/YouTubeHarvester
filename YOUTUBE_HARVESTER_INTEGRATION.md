# Интеграция YouTube Harvester с FriendsHub

Документ описывает готовый контракт интеграции. Изменять исходный код
YouTube Harvester со стороны FriendsHub не требуется.

## Поддерживаемая среда

Встраивание окна поддерживается только в X11 и XWayland. Для предсказуемого
результата FriendsHub должен запускать Harvester через XCB:

```text
env QT_QPA_PLATFORM=xcb yt-harvester --show-main
```

Для запуска из исходников путь должен задаваться в профиле FriendsHub, а не
быть зашит как `/home/user/YouTubeHarvester`:

```text
env QT_QPA_PLATFORM=xcb python3 /путь/к/tray_launcher.py --show-main
```

Команду следует запускать массивом аргументов без shell-конкатенации. Нативное
встраивание окна Wayland не поддерживается: у Wayland намеренно нет безопасного
аналога произвольного `XReparentWindow`. На Wayland без XWayland FriendsHub
должен открыть Harvester как отдельное окно.

## Идентификация окна

Qt-приложение публикует стабильные идентификаторы:

| Поле | Значение |
|---|---|
| desktop file | `yt-harvester.desktop` |
| `StartupWMClass` | `YouTubeHarvester` |
| `WM_CLASS` instance | `tray_launcher.py` |
| `WM_CLASS` class | `YouTubeHarvester` |
| размер главного окна | `900×620` |

FriendsHub должен искать главное окно по второй части `WM_CLASS`, равной
`YouTubeHarvester`. Заголовок `^YouTube Harvester(?:\s|$)` допустим только как
резервная проверка: оконный менеджер может дописать к нему имя приложения.

Нельзя считать PID короткоживущей команды `--show-main` владельцем окна. Если
Harvester уже запущен, второй процесс передаст запрос первому и завершится, а
окно останется привязано к PID исходного процесса.

## Команда `--show-main`

Команда имеет одинаковое поведение в трёх состояниях:

1. Если Harvester не запущен, создаётся один экземпляр и показывается обзор.
2. Если он работает в трее, существующее главное окно создаётся или поднимается.
3. Если окно было закрыто, оно снова показывается без второго экземпляра.

Передача команды выполняется через приватный атомарный файл запроса. В Linux
каталог имеет права `0700`, файл `0600`, проверяются владелец, формат, действие
и возраст запроса. Запрос старше 30 секунд не выполняется.

FriendsHub не должен читать, создавать или удалять эти внутренние файлы. Для
показа окна всегда используется только публичная команда `--show-main`.

## Встраивание в FriendsHub

Рекомендуемый порядок:

1. Запустить команду профиля и до 15 секунд ждать X11-окно нужного `WM_CLASS`.
2. Проверить, что окно принадлежит текущему пользователю.
3. Встроить только главное окно в контейнер вкладки размером `900×620`.
4. Передавать окну фокус клавиатуры и обычные события мыши.
5. Диалоги, окно быстрого скачивания, архив и системные файловые диалоги
   оставлять отдельными transient-окнами; в контейнер их не переносить.
6. При закрытии вкладки отсоединить окно корректно, но не завершать Harvester.
7. Полностью завершать процесс только по явной команде пользователя «Выход».

После сбоя или перезапуска FriendsHub достаточно снова выполнить
`yt-harvester --show-main` и повторить поиск окна. Координатные клики, поиск
значка в трее и эмуляция мыши не нужны.

## Уведомление о загрузке

В настройках Harvester есть флажок «Системные уведомления». По умолчанию он
выключен. После включения событие создаётся только когда одновременно выполнены
все условия:

- post-processing завершён;
- итоговый файл перенесён из временной папки в папку загрузок;
- вариант видео успешно записан в подробный архив.

Повторная проверка уже имеющегося варианта уведомление не создаёт. Ошибка
уведомления не удаляет и не повреждает скачанный файл.

В Linux отправляется стандартный вызов
`org.freedesktop.Notifications.Notify` со следующими данными:

| Поле | Значение |
|---|---|
| app name | `YouTube Harvester` |
| summary | точное название видео, не более 180 символов |
| body | локализованное `Канал: <название>` |
| category | `transfer.complete` |
| desktop-entry | `yt-harvester` |
| custom hint | `x-friendshub-event=video-downloaded` |
| event id | `x-friendshub-event-id=<24 hex>` |
| channel hint | `x-friendshub-channel=<название без HTML>` |
| image-path | проверенная локальная обложка, если доступна |

FriendsHub может использовать это уведомление для карточки и непрочитанного
счётчика. Рекомендуется сбрасывать счётчик при открытии вкладки Harvester.

FriendsHub умеет безопасно декодировать локализованное HTML-тело, но Harvester
также передаёт `x-friendshub-channel` отдельным plain-text полем. Это устраняет
зависимость машинной интеграции от языка интерфейса и HTML entities.

Событие хранится в приватной очереди до принятия системным механизмом
уведомлений. При временной ошибке оно повторяется с тем же
`x-friendshub-event-id`; новый ID для retry не создаётся. После принятия событие
удаляется. Если процесс завершился между отправкой и удалением, FriendsHub
безопасно отбросит повтор по сохранённому event ID. Максимальный возраст
ожидающего события — 300 секунд.

В Windows текущий fallback через `QSystemTrayIcon.showMessage` является
допустимым стандартным уведомлением и подчиняется тому же флажку. Если позже
понадобится обложка в Windows toast, рекомендуется WinRT/AppUserModelID; для
интеграции FriendsHub на Linux это не требуется.

### Граница доверия

D-Bus hint не является доказательством происхождения: другая программа того же
пользователя теоретически может отправить похожее уведомление. Поэтому
FriendsHub может по нему только показать текст, изображение и изменить счётчик.
Нельзя выполнять команды, открывать произвольный путь, удалять файлы или менять
настройки на основании уведомления.

Перед отображением FriendsHub должен:

- ограничить длину текста и экранировать разметку;
- принимать только локальное изображение обычного формата с разумным лимитом
  размера;
- не обращаться к сетевому URL из `image-path`;
- спокойно игнорировать неизвестные hints и повреждённые значения.

Если FriendsHub читает вызовы `Notify` через монитор D-Bus, монитор должен быть
только пользовательским session bus. Не следует подменять системный сервис
уведомлений или запрашивать привилегии root.

## Проверка интеграции

Минимальный чек-лист FriendsHub:

1. Первый запуск открывает ровно одно окно Harvester.
2. Повторный `--show-main` не создаёт второй процесс приложения.
3. Закрытое главное окно снова появляется по `--show-main`.
4. Во вкладку попадает окно с классом `YouTubeHarvester`, а не transient-диалог.
5. Быстрое скачивание и файловые диалоги остаются отдельными и получают фокус.
6. Закрытие вкладки не останавливает текущую загрузку.
7. При выключенном флажке уведомление о завершении не появляется.
8. При включённом флажке одно успешно сохранённое видео создаёт одно событие.
9. Ошибка, остановка и уже архивированное видео не увеличивают счётчик.
10. В нативном Wayland FriendsHub отказывается от встраивания и открывает
    обычное отдельное окно.

Для этой интеграции не нужны сетевой порт, HTTP API, XID в настройках
Harvester, доступ root или изменение пользовательских файлов приложения.

## Замечания по эксплуатации

- шаблоны FriendsHub используют `/usr/bin/yt-harvester --show-main`,
  `WM_CLASS=YouTubeHarvester` и `QT_QPA_PLATFORM=xcb`;
- сборка нового `.deb` сама по себе не обновляет установленную копию в `/opt`.
  Перед приёмочным тестом пакет нужно установить, затем полностью перезапустить
  Harvester, иначе `/usr/bin/yt-harvester` продолжит запускать старый код;
- старый пользовательский профиль FriendsHub мигрирует на контракт версии 2
  при следующем запуске программы; для применения изменений уже работающий
  FriendsHub нужно один раз перезапустить;
- если старый профиль указывает на исходный `start_tray.sh`, миграция сохраняет
  соседний `tray_launcher.py` и его прежние каталоги данных. Новый профиль без
  такой истории использует `/usr/bin/yt-harvester`;
- путь к исходникам не хранится в поставляемом профиле. Для разработки его
  можно передать через `FRIENDSHUB_YOUTUBE_HARVESTER=/путь/tray_launcher.py`;
- системные уведомления Harvester по умолчанию выключены. Для карточек и
  счётчика FriendsHub пользователь должен включить их в настройках Harvester;
- FriendsHub предпочитает структурированный `busctl`, но резервный
  `dbus-monitor` также дочитывает category, event ID, канал и безопасную
  локальную обложку из полного вызова `Notify`;
- подтверждение `Notify` означает, что сервис принял сообщение, но не
  гарантирует, что окружение рабочего стола визуально показало его;
- Windows fallback проверяется тем же флажком. Отдельный полноценный тест
  поведения tray balloon следует выполнять на реальной Windows;
- если появится богатый Windows toast, нельзя передавать FriendsHub команды или
  произвольные пути через payload — прежняя граница доверия сохраняется.
