# Перенос Данных Android

Реализован 2026-10-03. Это механизм переноса, а не разрешение удалять beta:
сначала требуется проверить подписанный кандидат и резервную копию данных.

## Формат И Защита

- В Настройках добавлены «Экспорт данных» и «Импорт данных», с системным выбором
  файла `.ythbackup`. Для экспорта требуется отдельный пароль от 12 символов
  и его повторное введение. Пароль подписи APK для этого не используется.
- Файл целиком защищён AES-256-GCM; ключ выводится из пароля через
  PBKDF2-HMAC-SHA256, 600000 итераций. Случайные salt/IV создаются для каждого
  экспорта; заголовок аутентифицирован. Пароль не сохраняется в Git, логах,
  настройках или saved state. Окно пароля защищено от снимков экрана.
- Пароль или повреждённый файл проверяются до изменения базы. Формат имеет
  версию 1, строгую схему, предел 32 MiB/50000 записей и ограничение вложенности.
- Экспорт прочитывается обратно из выбранного хранилища и сравнивается с
  записанными байтами. Это подтверждает запись, но не заменяет хранение копии
  на независимом носителе и проверку импорта.

Используются стандартные криптографические API, а не собственный алгоритм.
Источники: [Android cryptography](https://developer.android.com/privacy-and-security/cryptography),
[OWASP: PBKDF2 work factor](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

## Что Переносится

Каналы с порядком и выбором разделов, ручная очередь с дорожками/субтитрами,
архив с вариантами и датами, скрытые отметки, расписания, задания загрузки,
пользовательские настройки и доступные Telegram-реквизиты. Реквизиты извлекаются
в памяти и заново шифруются Android Keystore назначения; старый Keystore не
копируется. Нечитаемые реквизиты блокируют экспорт, чтобы не выдать неполную
копию за полную.

Видео, временные части, логи, runtime и текущая harvest-сессия в файл не входят.
Экспорт требует остановленных загрузок/проверок. Незавершённые задания при
импорте становятся PAUSED с нулевым прогрессом и без старой публикационной URI:
возобновление будет новой передачей, а не продолжением неперенесённой части.
Расписания сохраняют время, но выключены до явного включения владельцем.

## Импорт И Восстановление

Импорт допускается только в пустую базу: существующие записи не удаляются и
не перезаписываются. Настройки назначения заменяются после подтверждения.
Все Room-записи и зашифрованный журнал восстановления импортируются одной
транзакцией. Если запись DataStore прервётся, журнал завершает восстановление
на следующем запуске. Он содержит шифротекст под новым Android Keystore,
а не открытый Telegram-токен. Повторный импорт в непустую базу запрещён.
Room schema 11 добавляет `pending_transfer` и `archive_relinks`; миграции
старых схем сохраняют прежние таблицы.

SAF-разрешения непереносимы. После импорта нужно заново выбрать прежнюю папку
и обновить доступность архива. Старые URI не становятся разрешениями и не
считаются достоверными: MediaStore ID на другом устройстве может указывать на
иной файл. Для доступных файлов экспорт сохраняет имя, размер и SHA-256;
перепривязка в выбранной папке требует совпадения всех трёх признаков и одного
подходящего файла. Подменённый файл не связывается даже при совпадении размера.
Ищутся непосредственные файлы выбранной папки, без рекурсивного обхода.
Для архива из нескольких папок следует по очереди выбрать каждую и обновить
доступность. Запись с недоступным файлом сохраняется как история.

Если запись архива помечена доступной, но её файл нельзя прочитать и ранее
проверенного отпечатка нет, экспорт блокируется. Нужно восстановить доступ или
обновить доступность архива. На API 29+ для перепривязки нужен SAF-выбор папки;
старые MediaStore-разрешения другого приложения не предполагаются сохранёнными.

## Обязательные Проверки

Локально прошли 149 JVM-тестов, включая формат, шифрование, лимиты,
аутентификацию заголовка/содержимого, проверку SHA-256 и отмену хеширования;
21 Python-тест ресурсов/скриптов. Debug lint: 0 ошибок, 24 предупреждения.
Изолированные тесты переноса/rollback/журнала и миграций схем прошли на
LDPlayer API 34/x86_64; реальный SAF-тест подмены и перепривязки тоже прошёл.
Итоговый общий device-прогон: `OK (35 tests)`, включая два UI-теста окна
пароля и проверку отказа экспорта при нечитаемых файлах/реквизитах. Live-тест,
неприменимый API <=28 и отдельные старые SAF opt-in сценарии в этот прогон
не включались и не засчитываются. Журнал:
`build/qa-dev32/transfer-regression-20261003.txt`.

dev33: оптимизированный exporter с прежней beta-подписью проверен на установленной
основной beta после обновления dev32 -> dev33 без удаления. Существующие записи
и байты настроек совпали с резервной копией. Экспорт через системный выбор файла
независимо расшифрован и сравнен с базой; отказ при неверном пароле и непустой
базе проверен. Исправлена невидимость результата в Настройках; успех и отказ
теперь видны рядом с кнопками. Повторная debug-регрессия: `OK (36 tests)`,
журнал `build/qa-dev33/transfer-regression-20261003.txt`. TalkBack не проверялся.

Дополнительная приёмка dev33: реальный экспорт основной beta импортирован через
интерфейс в отдельный non-debuggable пакет `.migrationqa` с постоянной подписью.
Записи проверены, старые URI сброшены, журнал очищен; после нового SAF-выбора
папки файл архива перепривязан с совпадением имени/размера/SHA-256. Шесть тестов
переноса в подписанном QA-пакете прошли, включая разные UID/Keystore и отказ
расшифровки старого шифротекста новым ключом. Исходная beta не изменена.
Границы и журналы: [MIGRATION-QA-dev33.ru.md](MIGRATION-QA-dev33.ru.md).

Перед публичным выпуском остаются: повторная приёмка точного публичного кандидата,
восстановление файлов из нескольких папок, запуск на ARM/API 26/35+,
проверка большого реального архива и системного выбора файла при перезапуске.
Основная установленная beta не удалялась; она обновлена до dev33 с прежней подписью.
Не удалять исходную установку или её медиа до проверки копии и плана перехода.
